1. Remember that in UVM, test is not the root but uvm_top.
2. When you want to use UVM, everything you implement will be handled by different phases
3. Knowing the parent is required in uvm_component because it is a requirement whenever 
   constructing this class
4. uvm_test is child, uvm_top is the parent
5. a trick for the structure of a function or task inside a uvm class: 
   - function requires super.<method> while the task doesn't
6. If you create an instance of a component class and the parent is pointing to null, then
   uvm_top is the parent class like for ex:
   comp c;
   initial begin
     c = comp::type_id::create("c", null);
     c.build_phase(null);
   end
   - in real tb, only uvm_test is the child of uvm_top
7. Only components are scheduled by the UVM phase engine and allowed to consume simulation time and exists in uvm topology tree
